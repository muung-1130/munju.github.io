## 1. 작업 요약

이틀 동안 Amazon Bedrock Knowledge Base를 이용하는 러닝 특화 RAG 서비스를 구축했다. 최초에는 Spring Boot 기반의 `ai-service`를 작성했고, 이후 FastAPI 기반의 `ai-rag-service`를 별도로 구성하여 가드레일, 러너 프로필 기반 답변, 오늘의 코칭 API, 데모 UI, Docker 실행 환경 및 Next.js 연동 문서까지 확장했다. 동시에 러닝 부상, 대회 준비, 다이어트, 복장·용품, 자료실 관련 RAG 원천 데이터를 정리했다.

## 5. 확인된 주의사항 및 후속 작업

### 5.1 Git 저장소 상태 복구 또는 초기화

최상위 `.git` 디렉터리는 존재하지만 현재 Git 명령에서 정상 저장소로 인식되지 않는다. 작업 이력 보존을 위해 `.git` 내부 상태를 점검하고, 복구가 불가능하면 기존 디렉터리를 보존한 상태에서 새 저장소 초기화 여부를 결정해야 한다.

### 5.2 비밀정보 관리 개선

현재 예제 설정과 문서에 AWS 리소스 식별자, 내부 네트워크 주소 등의 구체적인 값이 포함되어 있다. 공개 저장소 또는 외부 전달 전 다음 조치가 필요하다.

- 실제 리소스 식별자를 플레이스홀더로 교체
- `.env` 및 AWS 자격 증명 파일이 Git에 포함되지 않도록 확인
- Docker Compose 예제에서 환경별 값을 외부 환경 변수로 분리
- IAM 권한을 Knowledge Base 조회에 필요한 최소 권한으로 제한

### 5.3 한글 인코딩 정리

일부 README, Next.js 연동 문서 및 파일 설명 문서에서 한글이 깨져 보인다. 해당 파일을 UTF-8로 통일하고 데모 질문·응답 예제를 다시 확인해야 한다.

### 5.4 테스트 자동화

현재 PowerShell 기반 API 점검 스크립트는 있으나 단위·통합 테스트 파일은 확인되지 않았다.

권장 테스트 범위:

- 가드레일 허용 및 차단 사례
- 프로필 입력값 검증
- Bedrock 오류 변환
- 세션 ID 유지
- 출처 URI 추출
- CORS 설정
- 오늘의 코칭 응답 파싱

### 5.5 서비스 구현 통합 방향 결정

Spring Boot와 FastAPI 구현이 병존한다. 실제 운영 아키텍처에 따라 다음 중 하나를 결정해야 한다.

1. FastAPI를 독립 AI 마이크로서비스로 운영하고 Spring/Next.js가 호출
2. Spring Boot 구현으로 기능을 통합
3. FastAPI를 검증용으로 유지하고 운영 서비스만 별도 선정

현재 구현 범위만 보면 가드레일, 개인화, 데모 및 Docker 구성이 포함된 FastAPI 서비스가 기능적으로 더 확장되어 있다.
