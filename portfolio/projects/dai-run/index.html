01 / The context

DAI RUN은 러닝 기록과 코스 탐색, 크루 활동, 러닝화 관리와 AI 코칭을 결합한 팀 프로젝트입니다. 애플리케이션 기능 개발과 함께 온프레미스 환경에서 AWS EKS로 배포·운영 환경을 이전했습니다.

저는 CI/CD와 Site-to-Site VPN 구축을 맡았습니다. 변경 사항이 배포까지 이어지는 흐름을 구성하고, 서로 다른 네트워크 환경을 연결하는 작업을 진행했습니다.

아래 배포 흐름은 팀 시스템의 일부입니다. 프론트엔드·MSA·AI 기능을 포함한 전체 서비스와 개인 담당 업무를 구분해 소개합니다.

02 / Delivery architecture

애플리케이션 변경에서 클러스터 반영까지
01 / BUILD & CHECKGitLab CI/CD변경 서비스 빌드 · 보안 검사
02 / IMAGEAmazon ECR이미지 저장 · digest 식별
03 / DECLAREGitOps repository배포 매니페스트 갱신 · MR
04 / DELIVERArgo CD → EKS상태 동기화 · Rollouts

배포할 이미지를 digest로 식별하고 GitOps 저장소에 반영합니다. Argo CD는 선언된 상태를 클러스터에 동기화하며, 프론트엔드에는 Argo Rollouts의 Blue/Green 배포 구성이 적용되어 있습니다.

03 / Work notes

담당 작업과 문제 해결 기록
01 / CI/CD MIGRATION

환경이 바뀌어도
배포가 이어지도록.

과제 — 온프레미스 Jenkins·Harbor 환경의 배포 흐름을 AWS 환경에 맞게 이전해야 했습니다.

작업 — GitLab CI/CD와 ECR, GitOps MR 반영을 연결하고 이미지 digest를 기준으로 배포 산출물을 추적하도록 구성했습니다.

GitLab CI/CDECRArgo CD
02 / HYBRID NETWORK

네트워크의 경계를 넘어
서비스를 연결.

과제 — 제한된 네트워크 권한과 NAT 환경을 고려해 온프레미스–AWS 연결을 설계해야 했습니다.

작업 — strongSwan과 AWS VPN 구성을 바탕으로 IPsec/IKEv2, NAT-T, 정적 경로를 검토하고 제약에 맞게 PoC 범위를 조정했습니다.
